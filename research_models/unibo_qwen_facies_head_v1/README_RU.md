# Исследовательская голова распознавания шести фаций

Обученный небольшой классификатор на **замороженных визуальных признаках исходной Qwen3-VL-2B-Instruct**. Это не LoRA, не `best.pt` сегментации и не новая чатовая модель. Базовые и языковые веса не включены и не изменены.

На 50 отложенных фотофрагментах UniBo: 26/50 (52%), macro-F1 0,4861. Ранее VLM с генерацией классов давала 16/50 (32%). На train — 338/352 (96%): разрыв большой. Продельта остаётся слабой (1/10). Три S-группы проверки коррелированы, выборка разработки многократно использовалась при исследовании; это не независимая итоговая точность и не точность всего CV-1.

Классы: хорошо/плохо дренируемая пойма, продельта, торф, русловой песок, болото. Нет автоматического соответствия с 92 фациями проекта. Предсказывается один из этих шести классов, неизвестные фации не отвергаются. Оценки линейной головы не являются вероятностью правильного геологического вывода.

Переносить каталог целиком. Веса головы — 393 488 байт; нормализатор включён в тот же safetensors. Нужна точная исходная HF-база, указанная в `MODEL_CONTRACT.json`, с тем же полным SHA256. Другие версии, квантованные или адаптированные веса данным контрактом не проверены. Автоматического скачивания и подключения к приложению нет. Стандартный EXE этот каталог не включает.

Исследовательский запуск из корня репозитория для **одной заранее вырезанной однородной области керна**:

```powershell
python scripts/classify_with_qwen_facies_head.py --model-dir research_models/unibo_qwen_facies_head_v1 --base "D:\models\Qwen3-VL-2B-Instruct" --core-crop "D:\core\interval.png"
```

Команда требует CUDA и окружение проекта, проверяет хеши, возвращает русский класс и численные оценки. Она не сегментирует фото ящика и не формирует подробное описание. Проверки на новых скважинах и подтверждение геолога ещё нужны.
