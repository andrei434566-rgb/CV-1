# Обучение различению всех шести классов: v8 и визуальный LoRA v9

Продолжено **локальное обучение Qwen3-VL-2B на уже подготовленных интернет-фотографиях керна**. Новые снимки в этом опыте не добавлялись. Проверены два разных способа обучения: нелинейная классификационная голова и настоящий LoRA визуального энкодера. Приложение продолжает использовать прежнюю модель: оба новых кандидата не прошли условия сохранения качества всех классов.

## Данные и критерий

Использован прежний проверенный набор v7: **804 вырезки, 798 точных меток и 6 общих пойменных A/B**. Это коррелированные фрагменты опубликованных фотографий, а не 804 независимые скважины. Фотографии, координаты, цвета и авторские метки не изменялись. Специалист проекта новые материалы ещё не утверждал.

Сохранены три прежних групповых fold: все снимки нового источника удерживаются вместе, старые S-группы UniBo не перемешиваются. Нормализация строится по обучающей части. Для общего пойменного примера обучается только принадлежность A+B, тип дренирования не выдумывается.

Критерий до проверки val: **полнота и F1 каждого из шести классов не ниже v3, macro-F1 выше** на одинаковых старых 722 точных OOF-метках. На val дополнительно требуются отсутствие падения точности и выполнение тех же условий для всех классов. Условия проверяются одновременно; общий прирост не скрывает ухудшение отдельного класса.

Val содержит прежние 50 вырезок и многократно использовалась в разработке. Это контроль разработки, а не независимая оценка на новых скважинах. Закрытые проектные test-пиксели не открывались. Шесть исходных обстановок **не равны 92 фациям проекта** и не измеряют качество полного описания керна.

## Что обучено

**v8 — RBF-голова.** Визуальные и языковые веса Qwen заморожены. Использованы 4096 признаков среднего/стандартного отклонения post-merger токенов. Нормализатор и медианная ширина RBF вычисляются только по train каждого fold. Проверены 18 сочетаний: три ширины, три регуляризации, две схемы балансировки классов/источников. Ни одно не прошло все условия OOF. Диагностический кандидат выбран по заранее заданному правилу, до загрузки val: factor0,5, alpha1, балансировка по классам.

**v9 — настоящий визуальный LoRA и остаточная голова.** Обучены qkv/proj последних четырёх блоков энкодера: rank8, alpha16, **196608 визуальных параметров**, плюс 24582 параметра поправки головы. Языковая часть Qwen не загружается и не обучается. Это классификатор вырезки керна, не новый чатовый или описательный LoRA для PEFT.

Один фиксированный рецепт v9: три эпохи, batch4, AdamW, LR визуального LoRA0,0001 и головы0,0005, clip1. Сохраняются прежние корректные точные примеры через KL к исходной голове; частичные A/B в этот teacher-критерий не попадают. Нормализатор и исходная голова каждого fold строятся только по старым train-строкам. Используется последняя эпоха, выбора checkpoint по val нет. После трёх OOF-обучений рецепт фиксируется; финальный адаптер обучается на всех804 строках и только после этого проверяется на val.

У v9 улучшение OOF по A/B/C/F сопровождается падением полноты D/E и F1 E. На val не исправлено ни одной прежней ошибки и добавлено две: по продельте и болоту. Даже при сохранённой полноте A/B их F1 снизился из-за ложных срабатываний. **Этот адаптер не заменяет рабочую модель.**

На собственных 798 точных train-примерах v9 даёт725/798, то есть90,85%. Это повторное распознавание обучающих данных; объявлять такую цифру достигнутой точностью проекта было бы неверно. Расхождение train/OOF/val показывает ограниченный перенос на другие изображения. Само увеличение числа эпох не доказано как способ исправить это.

## Проверки и устойчивость запуска

Перед обучением проверено точное совпадение признаков отдельного визуального загрузчика с исходным Qwen на двух реальных вырезках: максимальная разница0. Сохранена FP32-точность rotary-буферов; простое приведение всех буферов к FP16 меняло исходные признаки и было исправлено до обучения. Проверены реальные ненулевые градиенты и изменения весов LoRA.

Два последовательных длинных запуска прервались между группами без traceback Python; их частичные результаты не использованы для итогового кандидата. Аудируемый `v9_isolated` выполнен заново: **отдельный процесс на каждый fold и финальное обучение**, четыре кода завершения0. Это освобождает ресурсы процесса между загрузками моделей. Причина прежних остановок не установлена; исправление стабильности самого GUI здесь не заявляется.

Повторная загрузка сохранённых адаптеров выполняется отдельными процессами. Аудит проверяет SHA256 базы/процессора/источников/адаптеров, old-train-only prior и нормализатор, отсутствие пересечения source-групп, OOF, val-прогнозы и численные оценки. Для v8 дополнительно восстановлено решение уравнений: относительная невязка2,04×10⁻¹⁴. Свежий инференс v8 по реальному изображению совпал с кешем по всем шести оценкам, максимальная разница0.

Прошли18 CPU-тестов: точная/частичная функция потерь, независимое решение связанной RBF-задачи, балансировка групп, запрет регрессии класса, сохранение исходного поведения при нулевом LoRA, реальные обновления, повторная загрузка, раздельное усреднение токенов разных изображений и прежние проверки prior/контракта.

Отдельно проверен инференс всей val50 по одному изображению и пакетами по четыре. Прогнозы совпали для всех50 изображений, в обоих режимах27/50. Некалиброванные численные оценки FP16 различаются максимум на0,004316 из-за формы пакета; численное равенство одиночного и пакетного инференса не заявляется. При повторении исходных пакетов оценки совпали с сохранёнными точно, максимальная разница0.

```powershell
python scripts/train_kernel_facies_v8.py --output ../vlm_core_v1/outputs/kernel_new
python scripts/audit_kernel_facies_v8.py --run ../vlm_core_v1/outputs/kernel_new
python scripts/run_vision_facies_stages.py --output ../vlm_core_v1/outputs/visual_new
python scripts/run_vision_facies_stages.py --audit --output ../vlm_core_v1/outputs/visual_new
python scripts/classify_research_vision.py --experiment ../vlm_core_v1/outputs/visual_new --image D:/core/crop.jpg
```

Последняя команда принимает вырезку интервала, возвращает шесть некалиброванных оценок и статус исследовательского кандидата. Она не формирует геологическое описание и не применяет классификатор ко всему ящику. Рецепт привязан к исходной HF-базе `Qwen/Qwen3-VL-2B-Instruct`, revision `89644892e4d85e24eaac8bacfd4f463576704203`, и версиям библиотек в паспорте. Один Git-clone без локальных данных/базы не является готовым воспроизведением опыта.

Следующий обоснованный этап — независимые скважины и проверенные контрастные пары одинаково выглядящих глин поймы/продельты/болота, включая их соседние интервалы и экспертные признаки.
