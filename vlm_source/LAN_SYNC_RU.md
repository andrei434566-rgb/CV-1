# Общий сбор данных керна в локальной сети

Первый этап уже реализован в `lan_sync.py`: компьютеры передают исходные фото,
Excel и документы в одну закрытую общую папку Windows. Центральный компьютер
проверяет SHA-256 каждого файла, хранит одинаковые файлы один раз и записывает
происхождение партии. **Импорт не запускает обучение и не подтверждает геологию.**
Для работы без командной строки есть `CoreSedSync.exe`: укажите папку
хранилища, папку новых материалов и нажмите соответствующую кнопку.

```text
ПК1 (VLM) ─┐
ПК2 (VLM) ─┼─> общая папка SMB ─> проверка и архив ─> геологическая проверка
ПК3 (данные) ┤                                       └─> будущая версия LoRA 2B
ПК4 (данные) ┘                                                 └─> ПК1–ПК4
```

## Один раз на центральном компьютере

Выделите папку на диске с достаточным свободным местом, например
`D:\CoreSedHub` (если диска D: нет, подойдёт другой диск). Запустите EXE на
центральном ПК: вверху окна будет показано имя этого компьютера в сети.
Укажите локальную папку и нажмите **«1. Создать хранилище»**.

Затем откройте к папке доступ в Windows только тем учётным записям, которые
будут передавать данные: в Проводнике нажмите на папку правой кнопкой,
выберите «Показать дополнительные параметры» → «Предоставить доступ» →
«Отдельные люди». Дайте им право записи. [Инструкция Microsoft по общей
папке](https://support.microsoft.com/en-us/windows/experience/connectivity-networking/file-sharing-over-a-network-in-windows).
Если общая папка названа `CoreSedHub`, её адрес на остальных ПК будет вида
`\\ИМЯ-ПК\CoreSedHub`. Папка не должна быть общедоступной в интернете.
Для постоянной работы ограничьте клиентским учётным записям запись каталогом
`incoming`; `objects` и `catalog` должны изменяться только на центральном ПК.

```powershell
python lan_sync.py init --hub "D:\CoreSedHub"
```

Команду выше можно не вводить: её выполняет кнопка EXE.

На других ПК должен быть доступ к этому же хранилищу по сетевому адресу.
Пока программа не создаёт папку общего доступа Windows и не меняет права SMB:
это настройка компьютера владельцем сети.

## Отправить новые материалы с любого ПК

Сложите материалы одной партии в отдельную папку. Можно передавать исходные
фото и Excel без модели. Если на ПК работает локальный ИИ-седиментолог,
можно также передать его `data\app_sessions` как источник черновиков и правок.

```powershell
python lan_sync.py submit --hub "\\TRAIN-PC\CoreSedHub" --pc PC1 --source "D:\Новые керны\Скважина-101" --source-id "Скважина-101" --kind raw
```

В `CoreSedSync.exe` это кнопка **«2. Передать папку»**.

Для каталога записей приложения:

```powershell
python lan_sync.py submit --hub "\\TRAIN-PC\CoreSedHub" --pc PC2 --source "D:\CoreSed\data\app_sessions" --source-id "app_sessions_PC2" --kind app_sessions
```

Программа принимает фото JPEG/PNG/WebP/TIFF/BMP, Excel/CSV/TSV, PDF/DOCX,
JSON/JSONL/TXT и архивы ZIP/7z. Она пропускает временные Excel-файлы,
символические ссылки и служебные каталоги моделей. Пакет появляется в
`incoming` только после полного копирования. Если передача прервётся, программа
попытается удалить незаконченный пакет. Если сеть недоступна и скрытая папка
`.upload-...` останется на сервере, центральный импорт её пропустит; после
проверки причины папку можно удалить вручную.

## Принять партии на центральном компьютере

```powershell
python lan_sync.py ingest --hub "D:\CoreSedHub"
python lan_sync.py status --hub "D:\CoreSedHub"
```

В `CoreSedSync.exe` это кнопки **«3. Принять пакеты»** и
**«Показать состояние»**.

После импорта файлы находятся в `objects` под именем SHA-256, а записи о партиях
и исходных путях — в `catalog\receipts`. Повторный импорт уже принятой партии
безопасен. При несовпадении размера или SHA-256 партия отклоняется.

## Как данные попадут в одну модель

Следующий этап — экран проверки пар «фото — интервал — описание», чтение Excel
и выпуск версионированного обучающего манифеста. Для каждого примера нужны
скважина, глубины, конкретная область фотографии, исходный текст и имя
проверившего геолога. Черновые ответы VLM и только автоматически сопоставленные
файлы должны оставаться кандидатами. После проверки центральный компьютер
обучает новую LoRA для Qwen3-VL-2B на новых и прежних одобренных примерах,
сравнивает её с предыдущей версией на неизменных отложенных скважинах и
раздаёт одобренный адаптер на ПК1–ПК4.

Это позволяет всем компьютерам пополнять **один корпус и одну выпускаемую
версию модели**, не объединяя одновременно меняющиеся веса разных машин.
