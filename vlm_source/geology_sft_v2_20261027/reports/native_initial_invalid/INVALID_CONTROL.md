# Первый native-прогон: неверный контроль, 28.10.2026

Эти 32 запроса и их слепые оценки сохранены **только как аудит ошибочного
экспериментального контроля**. Они не являются результатом сравнения базы и
дообученной модели; счётчики качества по ним не публикуются.

Предполагаемая база отправляла `lora: []`. В сервере llama.cpp b11913 пустой
список возвращает глобально настроенные адаптеры. Непустой явный список сначала
обнуляет масштабы остальных адаптеров и затем применяет заданные значения.
Глобальная конфигурация загруженного адаптера имела scale 1; флаг
`--lora-init-without-apply` не превращает её в scale 0 для последующих запросов.
Поэтому отсутствие LoRA в условии «база» здесь не подтверждено.

Основание: [разбор request LoRA в server-context.cpp b11913](https://github.com/ggml-org/llama.cpp/blob/b11913/tools/server/server-context.cpp#L1764-L1778)
и [разделение загрузки/начального применения в common.cpp](https://github.com/ggml-org/llama.cpp/blob/b11913/common/common.cpp#L1392).
GET со списком загруженных адаптеров подтверждает ID и путь; одного этого GET
недостаточно для подтверждения эффективного состояния каждого запроса.

Правильный повторный опыт должен явно отправлять один и тот же ID со scale 0
для базы и scale 1 для кандидата. Он хранится отдельно и не перезаписывает
этот первый прогон.

В этом каталоге нет `native_result.json` и нет утверждения о приросте качества.
Сырые ответы и оценки, включая неверные геологические утверждения, являются
материалом аудита и исключаются из справочного поиска. Фотографии и бинарные
веса не включены. SHA256 и преобразование только локальных путей записаны
в `evidence_provenance.json`.
