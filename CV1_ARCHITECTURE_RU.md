# CV-1: геометрия YOLO и описания локальной Qwen

Рабочая схема для новых фотографий:

```text
Фото → выбранный best.pt (segment) → реальные полигоны интервалов
     → вырезки внутри полигонов → локальная Qwen3-VL-2B [ + LoRA ]
     → текст, привязанный к каждому полигону → проверка геологом
     → проект, редактирование, итоговый Excel по закреплённому шаблону
```

## Как попробовать

1. Запустите актуальный исходный проект CV-1 через `launch_latest.py` или `run.py`.
2. В настройках ИИ укажите локальные Python с CUDA и папку базовой **Qwen3-VL-2B-Instruct**. Сначала выберите **«Базовая модель»**.
3. Добавьте свой `best.pt` через **«Добавить файл»** в чате либо выберите модель сегментации в инструментах. Нужна задача `segment`; модель только с прямоугольниками не подходит.
4. Добавьте фото в чат. Если `best.pt` подключён, фото появится в проекте и пройдёт последовательный анализ геометрии и описаний. После обработки откройте карточку слоя, исправьте фацию, признаки и текст.
5. Заполните паспорт скважины и интервалы долблений, сохраните проект и выгрузите Excel. Пользовательский шаблон Excel сохраняется.

Последний выбранный `best.pt` запоминается между проектами и запусками:
заново выбирать его для каждой фотографии не нужно. Если исходный файл
перемещён или удалён, приложение сообщает об этом, сохраняя прежний выбор
до указания нового файла. Запоминание пути не удерживает YOLO в CUDA:
память GPU по-прежнему освобождается перед этапом Qwen.

Без `best.pt` можно беседовать с Qwen по фото и по теории; автоматических полигонов слоёв при этом нет. Если Python или базовые веса не настроены, программа сообщает причину и оставляет контуры без выдуманного описания.

Инференс работает **локальным постоянным процессом**, без адреса сервера и доступа к интернету. YOLO и Qwen используют GPU последовательно. Первый запрос включает загрузку весов; следующие интервалы используют тот же процесс Qwen. Новая схема входит в исходный код; ранее скачанный EXE сам по себе не обновляется.

Для ручной правки нажмите на интервал собранной колонки: откроется форма с глубинами,
цветом, зернистостью, текстурой и остальными списками справочника. На исходном фото
карточку можно открыть правой кнопкой или двойным нажатием. Геометрию редактируйте
отдельно через «Правка разметки → Изменить границы».

Команда в чате **«переопиши все фото»** обновляет автоматические черновики текущего
проекта. Проверенные специалистом описания, вручную изменённые интервалы, глубины и
контуры сохраняются. Для уже открытого проекта эта команда нужна, если в нём остались
старые неудачные автоматические описания.

В прямом CUDA-режиме до пяти фрагментов одного фото обрабатываются одним вызовом
модели, с отдельными изображениями и ответами для каждого интервала. Разные образцы
не склеиваются в общий снимок. При нехватке памяти используется последовательный
запасной путь; он сохраняет все задания, но работает медленнее. Первый анализ также
включает загрузку весов; скорость после загрузки нельзя выдавать за время холодного старта.

## Разделение ответственности

**YOLO** возвращает реальные `masks.xy`, координаты и оценку геометрии. Старые имена классов сохраняются только как происхождение прогноза. Справочник фаций, встроенная текстовая голова, эвристическая нарезка и автоматическое заполнение пропусков в новом маршруте отключены. Контуры могут пересекаться с границами физических столбиков; такие столбики остаются отдельным предварительным этапом и требуют проверки.

**VLM** получает вырезку из исходного фото; фон вне полигона скрыт. Она возвращает шесть текстовых полей: название фации, литология, текстура, ассоциация фаций, обстановка, описание. Для неподтверждённой интерпретации предусмотрено «Не установлена по фото». Если YOLO не нашла ни одной фациальной маски, найденные физические столбики всё равно собираются в общий керновый столбик, а VLM описывает каждый целиком; для длинного столбика в модель передаются верхняя, средняя и нижняя части. Такая рамка не выдаётся за маску фации и не попадает в обучающие пары. Изображение для Qwen уменьшается до рабочего размера модели, поэтому очень мелкие признаки могут быть неразличимы. Наличие правильного JSON не подтверждает геологическую правильность.

В автоматический запрос больше не подставляется меню редких текстур. В ручной форме
полный справочник сохранён. Прямой CUDA-маршрут ограничивает название породы вариантами
пользовательского справочника с пометкой предположения или неопределённости; это ограничение
словаря, а не доказательство определения. Очевидная подмена фации или ассоциации названием
породы помечается для проверки, исходный ответ сохраняется в атрибутах проекта.

**Объединение** сохраняет исходную геометрию и глубины соответствующего детектора. Для YOLO сохраняется confidence геометрии; он не является уверенностью в литологии или фации. Запоздавший ответ не перезаписывает изменённый, удалённый или подтверждённый специалистом объект. Соседние маски с одинаковыми описаниями не объединяются при экспорте. Пропуски и пересечения сохраняются как замечания в проекте; фиктивные фации вместо них не создаются.

## Подключение LoRA

В настройках доступны **«Базовая модель»** и **«Модель с дообучением»**. В базовом режиме сохранённые пути старых адаптеров не используются. Для второго режима укажите папку с `adapter_model.safetensors` и `adapter_config.json`. По умолчанию один адаптер используется для фото и общения; отдельный текстовый адаптер остаётся необязательной настройкой.

База, архитектура и версия должны соответствовать обучению. До выделения CUDA-памяти приложение проверяет локальные метаданные. При переносе переименованной папки помогает `cv1_adapter_manifest.json` с исходным ID, revision и SHA256 конфигурации базы. Проверка конфигурации не доказывает совпадение всех весов. Если точная revision неизвестна, она не объявляется проверенной. Известные отклонённые экспериментальные адаптеры блокируются; скрытого перехода на другую модель нет.

Веса базы и LoRA хранятся отдельно. Слияние весов сейчас не требуется. Для другого компьютера нужны приложение, совместимая среда CUDA/Python, локальная база, выбранный проверенный адаптер и ваш `best.pt`. Исходные учебные фото для работы модели не обязательны. Перенос описан в [инструкции](transfer/README_RU.md).

## Данные и следующее дообучение

Интернет нужен для подготовки данных, но не для работы приложения. Собираем максимально полезный проверяемый материал по трём направлениям:

- **Фото интервала + исходное описание:** проверяем соответствие фото, глубины и текста; не переносим описание всей скважины на случайный фрагмент.
- **Фото + название породы:** отдельная короткая задача классификации. Такие данные не содержат готового полного описания фации.
- **Теория:** краткие русские вопросы и ответы по первоисточникам с журналом происхождения. Текст без фото не учит модель непосредственно видеть признак на изображении.

Учитываются условия источников, точные дубликаты, разделение по скважинам/образцам и отдельный контроль. Ошибки подписи, неясное соответствие фото и текста и неизвестные числовые классы остаются вне обучения до проверки. [Реальные результаты трёх завершённых прогонов](QWEN_ROUND2_RESULTS_2026-10-26.md) и [новые кандидаты источников](vlm_source/theory_round2/CORE_DESCRIPTION_SOURCE_LEADS_2026-10-26.md) сохранены отдельно. Эти прогоны не достигли требуемого качества и не заменяют рабочую базу.

Для накопления своих пар в карточке слоя отдельно подтвердите **«Фация и границы проверены»** и **«Описание проверено — использовать при обучении ИИ»**. Экспорт проверенных пар сохраняет текст, вырезку и происхождение. После изменения полей, глубины или контура подтверждение текста становится недействительным до новой проверки. Автоматические ответы не становятся правильными учебными целями сами по себе.

Следующий адаптер сначала проверяется на независимых скважинах и одинаковых контрольных вопросах: качество пород/фаций, описаний, неопределённости, отсутствие обрывов и регрессии общения. Только затем его выбирают в настройках. Показатель 90–95% нужно определять для конкретной задачи; завершение обучения его не гарантирует.
