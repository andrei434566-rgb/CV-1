# Обновление CV 1 без пересборки EXE

Исправление неполных описаний VLM опубликовано в `main` и выпуске `cv1-v2.1.1`.
Для полного клиента 2.1.0 EXE служит запускателем и читает код из `_internal/app`.
Поэтому исправление можно применить заменой пяти Python-файлов. Модели,
сохранённые проекты, настройки и подтверждённые правки остаются на месте.

## Если приложение запускается из исходников в VS Code

1. Сохраните проект и закройте CV-1.
2. В папке репозитория выполните `git status`. Сохраните свои незакоммиченные
   изменения отдельным коммитом или через `git stash`, чтобы они не потерялись.
3. Выполните `git pull --ff-only` и запустите приложение обычным способом.
   Если Git сообщает о расхождении веток или конфликте, сначала объедините
   изменения. Команды принудительного сброса для обновления не нужны.

## Если используется установленный полный клиент 2.1.0

1. Скачайте `CV1_Code_Update_2.1.1.zip` из релиза
   [2.1.1](https://github.com/andrei434566-rgb/CV-1/releases/tag/cv1-v2.1.1).
2. Сохраните проект и полностью закройте CV-1.
3. Распакуйте ZIP в отдельную временную папку. Сохраните резервную копию папки
   `_internal/app` установленного приложения.
4. Скопируйте папку `_internal` из архива в папку, где лежит используемый
   `Kern_Analyzer.exe`. Подтвердите объединение папок и замену пяти файлов.
   Итоговый путь к одному из файлов должен быть
   `_internal/app/infrastructure/description_output.py` рядом с прежним кодом.
5. Откройте приложение прежним EXE или ярлыком.

Этот архив предназначен для полного клиента 2.1.0 с внешней папкой кода
`_internal/app`. Для более старой сборки, которая хранит Python-код внутри
самого EXE, используйте полный клиент 2.1.0 и затем этот архив.

## Повторная обработка

В чате приложения напишите **переопиши все фото**. Автоматические описания
будут обновлены; подтверждённые специалистом данные сохраняются.

При ошибке или автоматическом восстановлении создаётся локальный журнал
`Kern Analyzer Data/logs/vlm_diagnostics.jsonl`. В исходниках он находится в
`logs/vlm_diagnostics.jsonl`. Журнал различает остановку по лимиту токенов,
раннее завершение ответа, отсутствующие поля и некорректный JSON.

Пять заменяемых файлов: `description_output.py`, `local_vlm_runner.py`,
`local_vlm_client.py`, `core_description_prompt.py`, `main_window.py`.
Они совпадают с проверенным пакетом обновления 2.1.1. Повторное скачивание
моделей и установка нового EXE для этого варианта не требуются.
