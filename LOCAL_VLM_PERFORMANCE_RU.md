# Локальная VLM: отдельный чат и пакетные описания

Чат принимает вопросы и вложения независимо от обработки проекта. Прикрепление
фото или Excel само по себе не запускает сегментацию, импорт в проект или обучение.
Команда «обработай фото» / «собери колонку» запускает обработку явно. Вопрос по
фото получает ответ только в чате. Ответ и поправка специалиста сохраняют связь
с исходным вложением, даже если пользователь уже выбрал другое фото.

На GPU хранится одна модель. Пакетные описания используют до четырёх декодеров
одного llama.cpp, а вопросы получают приоритет после текущего пакета. Простые
ответы и поиск по локальным материалам не ждут GPU. Обработка не блокирует окно
чата. Все подробные описания входят в завершение пакета; они не заменены
справочными шаблонами и не отложены до отдельного разговора.

## Контрольный замер 27 октября 2026

| Условие | Результат |
| --- | --- |
| Видеокарта | NVIDIA RTX 4060 Laptop, 8 ГБ |
| Вход | 10 разных фото керна, по 3 столбика на каждом |
| Получено | 30 отдельных описаний со всеми шестью полями |
| Время через настоящее приложение MainWindow → QProcess → VLM | 55,14 с |
| Независимый процедурный прогон того же конвейера | 59,62 с |
| Включено во время | загрузка фото, поиск столбиков, сборка колонок, холодная загрузка Qwen, все описания и проверка привязки |
| Кэш готовых ответов | выключен; использовалось обычное повторное использование префикса запроса |
| Геометрия | детектор столбиков; пользовательский YOLO `best.pt` в этом замере не подключён |
| Модель | локальная Qwen3-VL-2B, экспорт исходных весов в Q8_0; vision projector F16 |
| Runtime | официальный llama.cpp b11913, Vulkan, четыре слота одной модели |

Прежний Transformers runtime на одном контрольном ответе затратил 31,12 с
на генерацию 163 токенов; загрузка модели заняла 59,63 с. Новый runtime в
одиночном контрольном запросе выдавал около 98 токенов/с и загружался примерно
за 6 с. Эти цифры относятся к указанному компьютеру и контрольным входам.
Большее число масок на каждом фото, другой `best.pt`, GPU и одновременные
вопросы в чате изменят время. Замер скорости не является оценкой геологической
точности: фации, обстановка и неразличимые свойства остаются гипотезами для
проверки геологом. Автоматические результаты не становятся учебной разметкой.

Приложение тестировалось в изолированном проекте Qt offscreen, без изменения
текущего пользовательского проекта. Его инициализация интерфейса выполнена до
старта обработки; модель Qwen загружалась с нуля. Доступность чата во время
обработки проверена; дополнительные GPU-вопросы в скоростном прогоне не отправлялись.

Локальные отчёты находятся в `outputs/app_pipeline_benchmark.json` и
`outputs/cv1_pipeline_final/report.json`.
Фото, их описания, абсолютные пути и модельные бинарные файлы в Git не добавлены.

## Подготовка на другом компьютере

В окружении установленной Qwen выполните из папки репозитория:

```powershell
..\vlm_core_v1\.venv\Scripts\python.exe scripts\prepare_qwen_turbo_local.py
```

В VS Code то же действие доступно как задача **CV-1: ускорить локальный ИИ**.

Скрипт использует уже скачанные веса Qwen 2B. Он скачивает проверенный по SHA256
официальный GPU runtime (около 37 МБ) и официальный конвертер, затем локально
создаёт GGUF и projector. Повторно скачивать базовую модель не нужно. Для другой
папки исходной модели передайте `--base <папка>`. Результат располагается в
`..\vlm_core_v1\runtime\turbo`. После подготовки перезапустите приложение.

Во время распознавания Интернет не используется. Приложение управляет своим
скрытым дочерним процессом с одноразовым ключом и только локальным loopback-
соединением; пользователь не вводит URL сервера. Дочерний процесс завершается
вместе с Python worker, включая принудительную остановку.

Неподходящая базовая модель или активная отдельная LoRA не заменяются базовым
GGUF автоматически: для них сохраняется Transformers runtime. Специализированный
checkpoint можно сначала объединить с совместимой базой, затем экспортировать
отдельно. Переключение режима не теряет пути к адаптерам.

## Воспроизведение

```powershell
..\vlm_core_v1\.venv\Scripts\python.exe scripts\benchmark_cv1_app.py <фото1> <фото2> ... --output outputs\my_benchmark
```

Процедурный прогон с отдельным сохранением колонок и всех описаний доступен в
`scripts/benchmark_cv1_pipeline.py`. Для замера настоящих масок добавьте
`--model <best.pt>`. Скрипты не засчитывают
фото без найденного керна и возвращают ошибку, если описание хотя бы одного
объекта отсутствует или обрывается. Процедурный прогон также проверяет, что
VLM не меняет геометрию; оба прогона проверяют, что учебные примеры
не подтверждены автоматически.

Источники runtime: [официальный релиз](https://github.com/ggml-org/llama.cpp/releases/tag/b11913),
[мультимодальная работа](https://github.com/ggml-org/llama.cpp/blob/master/docs/multimodal.md).
