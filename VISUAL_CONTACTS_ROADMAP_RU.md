# CV-1 — контакты фаций, столбики и обучающие источники

## Реализовано на текущем этапе (визуальные контакты)

В Kern Analyzer: **Столбики → Переходы между фациями…**.

- Выбрать не-UV фотографию из проекта.
- Автоматически предложить интервалы по устойчивым изменениям текстуры внутри
  уже известных столбиков (если заданы) или после их автоматического поиска.
- Отобразить неровные контуры и отдельные линии переходов поверх исходной фотографии.
- При наличии глубин фото — показать приблизительную глубину контакта; без
  калибровки поле остается пустым.
- Сохранить предполагаемые контакты и неровные линии в локальный JSON.
- **Только после подтверждения** заменить маски выбранного фото на редактируемые
  черновые интервалы без назначенных фаций и без статуса «проверено».
  До нажатия кнопки «Создать редактируемые черновики» проект не меняется.

Технически повторно используется существующая функция
`create_automatic_interval_detections` и существующая эвристика криволинейных
границ `RuleBasedFaciesDetector`. Новой обученной сети для контактов пока нет.
Предполагаемый контакт может быть вызван бликом, трещиной, маркировкой образца,
прослоем или иным контрастом: это **предложение на экспертизу**, не геологический факт.

Тест: `python -m unittest -v test_visual_contact_audit.py`.
Проверка синтаксиса: `python -m compileall -q app/ui/windows/main_window.py app/ui/dialogs/visual_contact_review_dialog.py app/infrastructure/visual_contact_audit.py`.
При открытии PR запускается легковесная проверка GitHub Actions без GPU.

## Следующие этапы — ещё не реализованы в этом PR

1. **YOLO целых столбиков**: отдельный конвейер LabelMe CoreBreakout → YOLO,
   групповая валидация по скважинам, затем обучение и проверка
   на реальных фото CV-1. Код подготовки в другом PR (#1);
   готовых весов CoreBreakout `best.pt` пока нет.
2. **Контакты на реальных снимках**: сравнить найденные переходы с ручной
   экспертной разметкой; рассчитать полноту и ошибку вертикального положения
   в сантиметрах; отдельно проверить косые/волнистые контакты. Только после
   этого решать, какие модели обучать на экспертных масках.
3. **Непрерывная колонка**: использовать существующий `assemble_core_tape`
   и `build_core_tape.py`; улучшить UI-навигацию между колонкой, отдельным
   фото, глубиной и Excel. Контроль потери/повтора интервалов.
4. **ГИС и привязка глубин**: сопоставлять фото, Excel и каротаж по одной
   шкале и отмечать противоречия; не делать вид, будто пиксели привязаны
   к точным метрам без проверки линейки и направления.
5. **Справочник пород и похожие участки**: Mendeley, DCID, UKCS — отдельная
   литологическая модель/поиск эмбеддингов; не смешивать эти классы
   автоматически с нашими 92 фациями.
6. **VLM описаний**: IODP 362 и проверенные фото+Excel, обязательно
   проверка соответствия текста *конкретному интервалу* и удержание
   независимых скважин в финальном тесте.
7. **Геологические атрибуты**: цвет, зернистость, слоистость, трещины,
   биотурбация и др. — отдельные проверенные задания; не выводить
   невидимые свойства только из изображения.

## Лицензии и качество

UniBo и DCID отмечены как некоммерческие; не включать их в веса будущего
коммерческого CV-1 без разрешений. Лицензию конкретных изображений/разметки
CoreBreakout (BGS) проверять отдельно от лицензии исходного ПО. Манифесты
должны хранить ссылку на источник и условия использования.

Исходные фото, рабочие Excel, обученные веса и внутренние данные скважин
хранятся локально, а не автоматически в публичном репозитории.

Для полноценного внедрения остальных этапов нужны доступ к локальным архивам,
машина с CUDA-GPU и хотя бы небольшой эталонный набор подтверждённых границ
для честного контроля точности. Ни один пункт не означает, что VLM/YOLO уже
обучены на перечисленных наборах.
