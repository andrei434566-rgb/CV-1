# Расширение фото и выбор модели только по учебным S-группам

## Протокол до запуска

Исходный [классификатор на замороженных признаках Qwen](VLM_VISUAL_HEAD_2026-10-30.md) дал 26/50 (52%, macro-F1 0,4861), при 338/352 правильных учебных ответах. Основные слабые классы — продельта (1/10), хорошо дренируемая пойма (1/4) и плохо дренируемая пойма (3/8). Учебная точность уже высока, поэтому целью нового опыта является перенос между исходными группами, а не рост запоминания.

Добавлены 352 новых чистых учебных окна: всего **704**, из **49 исходных фотографий вместо 44**. Использованы пять ранее не представленных фото S2. Учебных S-групп стало 21 вместо 20; это группировочные признаки, не подтверждённые номера скважин. Продельты стало 64 окна вместо 32, но её исходных групп осталось три — независимого разнообразия это удвоение не добавляет.

| Класс | Старый train | Новый train |
|---|---:|---:|
| Хорошо дренируемая пойма | 64 | 128 |
| Плохо дренируемая пойма | 64 | 128 |
| Продельта | 32 | 64 |
| Торф | 64 | 128 |
| Русловой песок | 64 | 128 |
| Болото | 64 | 128 |

Метки получены только из точной авторской палитры. Чистота класса/переднего плана не ниже 98%, игнорируемые пиксели не более 0,5%. Дополнительные формы окон 96×96, 128×64, 192×96, 128×128, 256×128 позволили использовать более тонкие участки керна. Новое окно пересекает прежнее не более чем на 20% меньшей площади и IoU не более 0,1. Перепроверены оригинальные фото и маски; новые окна воспроизводят обработку JPEG-тайла quality94/subsampling0 перед PNG-вырезкой. Маски и подписи не становятся входом модели.

**Прежние 50 val-изображений и их метки не изменены.** Проектная test-часть не открывается. Исходный publisher Test был перегруппирован ранее и не считается закрытым тестом. Окна внутри одних исходных фото/групп коррелированы.

Источник: Andrea Di Martino, Alessandro Amorosi (2023), [Sedimentary Facies Analysis and Segmentation](https://amsacta.unibo.it/id/eprint/7308/), DOI 10.6092/unibo/amsacta/7308, CC BY-NC-SA 4.0. Кандидат остаётся отдельным некоммерческим исследованием.

## Модель и выбор параметров

Qwen3-VL-2B и её чатовые веса не меняются. Для прежних 352 окон используются проверенные сохранённые признаки; для новых 352 — тот же исходный замороженный энкодер и предобработка. Точная база проверяется по SHA256, версии библиотек — по контракту предыдущих признаков.

Добавлены вычисляемые из RGB цветовые/текстурные признаки: распределения яркости/цвета, локальный контраст, равномерные соседние паттерны, совместная встречаемость уровней серого и направленность градиентов. Они описывают изображение, а не физическую зернистость в миллиметрах и не генетическую обстановку напрямую. В исходной фотографии могут присутствовать особенности подготовки керна и съёмки.

Предварительно заданная сетка — 32 варианта: четыре профиля (все признаки Qwen, до merger, после merger, Qwen + отдельно нормированная текстура), четыре lambda (0,1; 1; 10; 100), два режима весов (равные классы; равные классы и S-группы внутри класса).

Для выбора используются **только 704 учебных примера**. Три групповых разбиения строятся по train-меткам: редкие группы продельты распределены между ними, каждый класс представлен в каждой проверочной части. Все окна одного исходного S-префикса остаются вместе. Средние/std, коэффициенты и веса каждого fold определяются только по его учебной части; прогнозы для остальных окон являются out-of-fold (OOF).

Правило выбора: сначала наличие ненулевой OOF-полноты всех шести классов, затем общий OOF macro-F1, средняя точность по S-группам, большая регуляризация и фиксированный порядок профилей. До оценки старой val сохраняется `selection_frozen.json`; по её результатам параметры не переизбираются. Классификатор финально пересчитывается на всём train с выбранными параметрами.

Это новое сравнение на многократно использовавшейся выборке разработки, не независимая итоговая проверка. Одновременно меняются покрытие данных, признаки, взвешивание и регуляризация — отдельно приписывать выигрыш одному фактору нельзя.

## Заранее заданные критерии

Прежний классификатор оценивается заново на тех же сохранённых признаках val. Для продвижения кандидата ожидаются: минимум 28/50 правильных ответов, macro-F1 не ниже 0,51613, ненулевая полнота всех шести классов, продельта не менее 2/10 и плохо дренируемая пойма не хуже 3/8. Это исследовательский порог прогресса, не приёмка для геолога и не сопоставление с 92 фациями проекта. Калиброванная уверенность и полное описание не обучаются.

Каталог опыта: `vlm_core_v1/outputs/core_qwen_facies_groupcv_20261030_v2`. Сохраняются происхождение, хеши, OOF-результаты всех вариантов, фиксированный выбор, финальные ответы и веса. Старый пакет не перезаписывается до проверки. Перед запуском прошли 18 CPU-тестов, включая отсутствие группового пересечения, веса, равенство базовому ridge и свойства текстурных признаков.

## Результат и решение

Опыт завершён; аудит выполнен 31.10.2026. Выбранный **только по train OOF** вариант: `qwen_post`, равные веса классов, lambda 1. Используются 4096 признаков после merger. Текстура участвовала в сравнении, но выбранный вариант её не использует; приписывать ей улучшение нельзя. Полный выбор 32 вариантов сохранён в `selection_frozen.json`.

| Проверка | v1 | Новый кандидат |
|---|---:|---:|
| Прежние 50 val-фрагментов | 26/50 (52%) | **27/50 (54%)** |
| Macro-F1 на val | 0,48613 | **0,55653** |
| Хорошо дренируемая пойма | 1/4 | 3/4 |
| Плохо дренируемая пойма | 3/8 | **2/8** |
| Продельта | 1/10 | 2/10 |
| Торф | 4/4 | 4/4 |
| Русловой песок | 11/12 | **9/12** |
| Болото | 6/12 | 7/12 |

Исправлены четыре старые ошибки, добавлены три новые; всего изменилось 12 ответов. По S10 результат остался 4/8, по S11 вырос с 7/20 до 8/20, по S21 остался 15/22. Этот небольшой прирост на повторно используемой выборке не доказывает улучшения на новых скважинах.

На train новый классификатор дал 649/704 (92,19%, macro-F1 0,92077). При удержании целых train S-групп OOF-результат выбранного варианта — 432/704 (61,36%, macro-F1 0,57540). Полнота продельты в OOF лишь 12/64. Разрыв с train и ограниченное разнообразие этой фации сохраняются.

**Кандидат не продвинут:** не выполнены два заранее заданных условия — минимум 28/50 и сохранение плохо дренируемой поймы не хуже 3/8. Остальные три условия выполнены. Порог после просмотра val не менялся, другой вариант по этой val не подбирался. v1 остаётся стандартным выбором исследовательской команды; настройки приложения и общий чат не менялись.

Отдельный [пакет кандидата v2](research_models/unibo_qwen_facies_head_v2_candidate/README_RU.md) содержит веса, нормализатор, контракт, метрики, полный выбор по train и итог аудита. Веса — 295 408 байт, SHA256 `b0a425a574680c605f55a3efa6cd5d58c5f5be49e07cfe693cf8ae80dfc92a89`. Пакет можно запускать явно для сравнений; автоматического подключения нет.

## Воспроизведение и проверка

При наличии локально подготовленных исходных архивов, прежнего опыта v1 и указанной в контракте базы:

```powershell
python scripts/expand_unibo_facies_train.py --old-data D:\data\unibo_vlm_facies --prepared D:\data\unibo_prepared --output D:\data\unibo_expanded
python scripts/train_facies_head_groupcv.py --data D:\data\unibo_expanded --reference D:\experiments\facies_head_v1 --output D:\experiments\facies_groupcv_new
python scripts/audit_facies_head_groupcv.py --run D:\experiments\facies_groupcv_new
```

Пути данных и v1 по умолчанию соответствуют рабочему дереву проекта; флаги `--data` и `--reference` задают другие расположения. Существующий каталог опыта не перезаписывается. Аудит также дополняет переносимый контракт версиями признаков и статусом приёмки. Исходные фотографии и кеш признаков не включены в Git.

`scripts/audit_facies_head_groupcv.py` повторно проверил все хеши исходных вырезок, разделение train/val, неизменность прежней val и правило выбора. Независимо восстановлены три групповых прогноза выбранного варианта и его нормализатор; относительная невязка финальных нормальных уравнений — 2,15×10⁻¹⁴. Аудит сохраняет OOF-ответы для каждой строки. До опыта прошли 18 CPU-тестов; после расширения переносимого запуска — 15 относящихся к нему тестов, включая три новых проверки совместимости v1/v2. Свежий офлайн-запуск из упакованных весов на CUDA повторил сохранённый ответ val и все шесть численных оценок с нулевой разницей; результат находится в `portable_smoke.json`.

Следующий содержательный шаг — расширить число независимых исходных примеров продельты и пойменных отложений, затем проверить на новых скважинах. Ещё больше похожих окон из тех же фото не заменяет такое покрытие. Текущий результат относится к шести исходным классам UniBo; он не оценивает 92 фации проекта, подробное описание или работу общего ассистента.
